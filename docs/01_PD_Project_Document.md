# 01. Project Document (PD): LaundryMann 2.0

## 1. Vision and purpose
LaundryMann helps a person decide **how to wash each garment safely** by looking at it. From a phone photo (single garment or a basket) it estimates colour family, likely fabric, visible stains and the care label, then produces an explainable wash plan and groups items into loads that will not damage each other.

**Purpose and role of the system:** perception (computer vision) proposes facts with calibrated uncertainty; a **rules engine grounded in care-label constraints** decides; the UI explains and lets the user correct. It replaces guesswork ("will this bleed?") with evidence, and never overrides a manufacturer's care label.

## 2. Problem statement
* People damage clothes by mixing dye-bleeders with light items, washing delicates hot, or setting stains with the wrong temperature.
* Existing appliance "AI" senses only after items are already in the drum and only for small loads, per vendor documentation (e.g. fabric sensing limited to 2-3 kg loads and reduced accuracy for mixed fabrics). It is also locked to specific machines.
* A phone-based assistant that works with any washer and reasons **before** loading is a real, unfilled niche.

## 3. Baseline: what v1 actually is (audit summary)

| Area | v1 reality | Consequence |
|---|---|---|
| Stain model | YOLOv8n, single class "stain", 3,044 labelled boxes; log shows 6 of 20 epochs, mAP50≈0.74 | Cannot say *what* stain; result not validated |
| Fabric model | Trained on garment-*type* images; weights absent; always returns "Cotton (Fallback)" | Fabric claims are false; Silk/Wool rules unreachable |
| Colour model | 32×32 CNN (~155k params) trained on labels **generated by HSV thresholds** | Circular: it imitates its own rule |
| Basket detector | COCO YOLOv8n (no garment classes) + edge fallback | "Multi-item" is unreliable |
| Sensors | E-nose/UV = two checkboxes | Not real; removed from scope |
| Decision engine | Hard-coded if/else → bins A-G; recipe table duplicated in 3 files | Unmaintainable, unexplained |
| Auth | Cookie holds plain username, unsigned | Account takeover |
| UIs | Tkinter + 2 Streamlit apps + vanilla JS page | Four products, none finished |
| Repo | ~56 MB of weights committed, Windows paths, Jupyter CMD in Docker | Not reproducible |

## 5. Scope

**In scope (v2.0):** single-garment analysis; basket analysis; colour/bleed classification; fabric estimate with abstention; stain localisation (type by user, suggestion later); care-label OCR + symbol recognition; explainable wash plan; load grouping; wardrobe; feedback/corrections; PDF wash guide; auth and privacy features; observability; CI/CD.

**Out of scope (documented as deferred):** commercial robotic sorting (conveyor, ROS, robot arm, Jetson); real E-nose/UV hardware; drying/ironing scheduling; LLM chat; native mobile apps; monetisation.

**Extension points kept (not built):** `observations`-style time-stamped records and a `treatments/outcomes` table sketch are noted in the DB doc so a future outcome-learning idea can plug in without a rewrite.

## 7. Success criteria (proposed; re-baseline in Phase 0)

| Capability | Metric | Target |
|---|---|---|
| Colour family (6 classes) | Top-1 vs human labels | ≥ 90% studio, ≥ 80% field set |
| Stain localisation | mAP@0.5; recall on field set | ≥ 0.60; ≥ 0.70 |
| Fabric family (+unknown) | Macro-F1; selective accuracy | ≥ 0.70; ≥ 90% at ≥ 50% coverage |
| Care symbols | Per-category accuracy (real photos) | ≥ 75% (≥ 90% synthetic) |
| Calibration | ECE after temperature scaling | ≤ 0.05 |
| Latency (CPU, 8 vCPU, 1 garment) | p95 | ≤ 2.0 s |
| Safety | Never-do rule violations | 0 |

The previous document promised "300 ms" and ">99.5% accuracy" with no measurement; those are withdrawn.

## 7b. Constraints and assumptions
* Solo developer, ~10-15 h/week; CPU-only laptop (v1 training took ~2 h for 6 epochs on CPU) → **train on free GPU tiers (Kaggle/Colab; quotas change)** and run inference on CPU via ONNX Runtime.
* Datasets are public and imperfect (see Dataset Plan); a **self-collected field set** is mandatory.
* Ultralytics YOLO26 is AGPL-3.0; acceptable for an open-source portfolio repo; an ADR documents the RF-DETR (Apache-2.0) alternative if closed-source use is ever needed.
* Assumption: users hold the phone camera 20-60 cm from the garment in normal indoor light.

## 8. Deliverables

## 9. Glossary

| Term | Meaning |
|---|---|
| ECE | Expected Calibration Error: gap between stated confidence and actual accuracy |
| Conformal prediction | Method that outputs a *set* of labels with a coverage guarantee; used to abstain |
| Selective accuracy | Accuracy on only the items the model chose to answer |
| ISO 3758 | International care-labelling symbol standard (wash, bleach, dry, iron, professional care) |
| Dye-bleed risk | Likelihood a coloured item releases dye onto others in the same wash |
| Hard constraint | A rule that can never be overridden (e.g. "dry-clean only") |
| ADR | Architecture Decision Record |
